## 一、使用原则与约束范围

### 1.1 如何使用

编写或修改文档前先读取本规范；完成后对照“交付检查表”检查实际页面。已有文档先沿用其正式标题和栏目，再整理栏目中的内容，不随意换一套目录。

要求的优先顺序为：本次明确要求 → 指定文档模板或现有正式结构 → 本规范默认约定。

### 1.2 范本格式与补充约定

| 项目 | 多份范本中的实际做法 | 本规范的使用方式 |
| --- | --- | --- |
| 标题层级 | 文档名称独立；多数正文使用“一、”“1.1”“1.1.1”，索引页使用语义栏目 | 使用真实标题层级；按文档类型选择是否编号 |
| 正文组织 | 短段落、带短标签的要求、并列列表、顺序步骤和子列表 | 按内容关系选择；同一事项集中成块 |
| 阶段文档 | SOP 每阶段重复“核心目标＋步骤”，步骤中写角色和依据 | 用于有阶段交接的流程文档，不强加给所有说明文档 |
| 图片与附件 | 放在对应小节或操作附近；部分图缺少独立图题 | 保留位置关系；新交付图文稿补充明确图号和说明 |
| 版本记录 | 文末原生四列表格，存在两种字段顺序、日期格式和表头底色 | 沿用已选模板；新建默认采用项目档案 A，见第五章 |
| 提示与复制内容 | 提示块、引用块、文本代码块各有用途 | 强调少量关键点；可复制材料与操作说明分开 |
| 文档入口 | 索引页按主题独立列出内联文档引用 | 保留真实链接和显示名，不将空白文字投影误判为空段 |

图号、中英文图注、刷新核验等是结合实际图文编辑需求补充的交付约定，不声称所有范本都完整使用了它们。范本里的空行、超宽表格、偶发跳级和无图题现象不作为必须复刻的格式。

不得照搬范本的工程参数、人员、版本历史、宣传任务或客户沟通承诺。原理图规范中的字体与电气条款作用于原理图，不扩大为所有文档的排版要求。

### 1.3 分阶段与副本边界

本次明确的阅读顺序也是约束。用户要求“仅用此技能先做，完成后再看其他范本”时，第一阶段只使用本技能已有规则与指定稿件、素材，不提前打开外部范本；完成实际排版、保存刷新和内容核对后再进行只读比较。新增规则区分范本观察与整理者补充约定，不把后验比较写成第一阶段已经参考的依据。

要求另存时，先建立云端副本并核对新旧网址，再编辑副本。原件、原正式入口及已有批注保持可追溯；不将“另存一份”解释为替换正式交付版。副本建立、权限继承、客户确认和正式发布是不同状态，不能互相代替。

## 二、文档标题、目录与编号

### 2.1 文档标题

标题应让读者一眼知道“哪个项目、什么文档”。必要时注明版本用途，例如“第一版”“客户版”或“内部版”。

推荐形式：`项目名称｜文档名称（版本或用途）`。已有正式名称时保留原名，不为了统一分隔符而擅自改名。

- 飞书的文档标题栏填写正式名称，不能留成“未命名文件”或“请输入标题”。
- 正文通常直接从第一章开始，不再重复一遍同名大标题。
- 如需展示方案名称或版本副标题，可增加一行简短说明，避免形成两个同级总标题。
- 独立 Markdown 文件保留一个 `# 文档标题`，便于在其他阅读器中识别。

### 2.2 标题层级映射

飞书文档的标题栏与正文标题是不同层级，不能把 Markdown 的标记数量直接照搬为飞书标题等级。

| 内容角色 | 编号示例 | 独立 Markdown 文件 | 飞书正文样式 |
| --- | --- | --- | --- |
| 文档名称 | 项目名称｜方案说明 | `# 文档名称` | 独立的文档标题栏 |
| 大章 | 一、项目背景与目标 | `## 一、项目背景与目标` | 一级标题 |
| 小节 | 1.1 项目背景 | `### 1.1 项目背景` | 二级标题 |
| 子小节 | 1.1.1 使用场景 | `#### 1.1.1 使用场景` | 三级标题 |

### 2.3 编号规则

1. 编号型文档的大章按“一、二、三……”顺序编号。知识库首页等语义栏目可以不编号；采用既有模板时沿用其方式。
2. 第二章下的小节使用“2.1、2.2……”，子小节使用“2.1.1、2.1.2……”。
3. 编号后统一留一个空格，不混用“1.1、”“1.1.”等不同写法。
4. 同级编号不得重复、跳号；移动或删除章节后要重新检查编号。
5. 有独立内容、需要进入目录的子小节必须有相应编号，不能把“时制与默认首页”等正式小节留成无编号标题。
6. 短提示如“操作方式”“注意事项”可在段首加粗，不必全部升级为目录标题。适用范围、责任角色、资料和版本等辅助栏目可使用无编号标题。
7. 通常不超过三级正文标题。确有问卷板块、操作分支等更深内容时先考虑段首标签或嵌套列表，必须设置标题时保持连续层级。既有范本有第四级标题，不代表新稿必须照搬。

范本中的“相关链接和任务进度同步”“版本记录”属于文末辅助栏目，可以不编号，但仍应使用与大章一致的标题样式。既有文档若已使用“五、版本变更”等正式栏目名称，应保留原栏目名称。

### 2.4 目录与内容对应

- 每个栏目只放与标题直接相关的内容。
- “交互流程”说明用户怎么进入、操作、结束；“界面稿与资源”展示对应画面及说明；“版本记录”记录实际修订。
- 不能把内部工作安排、邮件草稿、提示词或宣传文案混进客户功能说明。
- 不强制所有文档都使用同一套章节名称。按文档用途组织，已有正式目录优先。
- 交付前逐项点击目录，确认标题层级、编号和跳转位置正确。

## 三、正文语言与内容组块

### 3.1 面向读者表达

客户稿默认使用非专业人员也能理解的直接表达，先说“做什么、怎么操作、会看到什么”，再说明必要的技术原因。

专业英文术语首次出现时给出中文解释；后文保持同一种叫法。型号、引脚、变量名和文件名保留原样。

例如，用“启动倒计时后自动回到首页，顶部显示剩余时间”，不要只写“倒计时模块具备后台持续运行与首页状态映射能力”。

### 3.2 每段表达一个完整意思

- 同一条规则的条件、操作和结果应放在一起，不能拆到不同章节让读者拼接。
- 不把每一句话都单独拆成段落，也不把整个功能写成一大段。
- 同一功能的说明连续排列，不在中间插入其他功能的图片、链接或备注。
- 开头已经解释过的范围，不要在每一小节重复一遍。
- 不使用空段落、连续换行或成排分隔线撑开版面。

### 3.3 功能说明的推荐顺序

每个功能按下面的顺序组织，缺少某类内容时可以省略，不必强行凑齐：

1. **用途与入口**：这个功能做什么，从哪里进入。
2. **操作规则**：用户按什么、点什么或怎样滑动。
3. **状态与结果**：未开始、准备、运行、完成等状态如何变化。
4. **配图与图注**：展示刚才说明的状态，解释图中要点。
5. **必要补充**：退出方式、异常情况或相关限制。

### 3.4 列表、步骤与表格的选择

| 表达内容 | 应使用的形式 |
| --- | --- |
| 一段连续说明或原因解释 | 正文段落 |
| 没有先后关系的多个特点、要求、选项 | 无序列表 |
| 必须按顺序完成的操作 | 有序步骤 |
| 多个对象按相同字段比较 | 表格 |
| 页面状态之间的变化 | 简短流程或状态说明，必要时配图 |
| 修订历史 | 固定四列表格 |

一段步骤中使用动词说明操作；一组并列列表保持相似的句式。不要用“编号｜任务｜负责人”这样的纯文本行代替真正的表格。

## 四、图片、图题与图文对应

### 4.1 图片必须有明确用途

插图前先确定它解释哪一个段落或操作状态。图片必须放在对应小节中，不能先把图片统一上传，再把它们留在随机的段落位置。

推荐的阅读顺序为：**小节标题 → 简短说明 → 对应图片 → 图题与图注 → 必要补充**。如需先看图再解释，也必须让图和说明相邻。

### 4.2 单图与组图

- 一张图表达一个独立对象或状态时，单独放置。
- 同一功能的多个状态需要比较时，可按操作顺序并排展示。
- 对照图统一显示高度和视觉大小，不能一张特别大、另一张特别小。
- 并排后看不清文字时，减少每行图片数量或改为上下排列；清晰度优先于紧凑。
- 组图中给每个状态加简短标签，整组使用一个图号和共同图注。
- 不把不同功能或没有比较关系的图片拼成一组。

### 4.3 尺寸与清晰度

1. 图片等比缩放，不拉伸、不压扁。
2. 图片宽度不得超出正文阅读区域，正文和图注不能被挤出页面。
3. 可裁掉无用的外围留白，但不得裁掉状态栏、按钮、单位、数值、接口标识或其他关键内容。
4. 同类界面图采用统一的展示尺度；不同宽高比的图片通过边距或排布协调，不强行变形。
5. 放大低分辨率图片不等于增加清晰度，必须检查最终页面上的文字是否可读。
6. 原图保留，裁边、缩放和组图使用整理后的副本。

### 4.4 图号与图题

正式图文说明稿默认全篇连续编号：图 1、图 2、图 3……。已有项目明确使用分章编号时可以沿用，但同一文档不能混用两套编号。知识库导航中的文档图标、装饰图标不作为内容插图编号。

图题采用“图号 + 具体图名”，不能只写“效果图”“如下图”或直接使用图片文件名。

```text
图 1　呼吸测量的准备与运行状态
```

图题放在对应图片下方。飞书等支持原生“图题／图片说明”的平台，必须写入并绑定该图片的原生图题栏；普通正文居中、缩小或加粗都不能替代原生图题。不把图题设为章节标题。

纯 Markdown 等没有原生图题组件的载体，才使用紧随图片的普通文字作为兼容表达；将其转入飞书时仍需转换为原生图题。验收时逐图确认图题实际非空、绑定对象正确、保存刷新后保留，不能以存在空 caption 字段为通过依据。

### 4.5 图注要解释图片

图注应说明图中显示的状态、关键差别或操作含义，不能写一段与该图无关的通用介绍。

例如，图中展示“准备”和“运行”两个状态，图注应解释何时开始计时、哪一个操作记录事件；不要把未展示的历史记录或设置流程写进这张图的图注。

示例数值必须与图中一致。多张图使用相互独立的示例数据时，不应把它们写成一次连续操作的计算过程。

### 4.6 中英文图题与说明

面向客户且需要中英文展示时，优先复用同一张图，提供对应的中英文图题和说明，不为重复解释同一张图而再插入一张相同图片。

```text
图 1　呼吸测量的准备与运行状态
点击中央圆环进入准备状态；第一次按机械按键记录呼吸后开始计时。

Figure 1. Ready and running states of respiratory measurement
Tap the central ring to enter the ready state. Timing begins when the first breath is recorded with a physical button.
```

中文和英文使用相同的图号，状态、操作、单位和数值必须对应。如果采用独立的中文、英文两份文档，两份文档也应保持相同的图片顺序和图号。纯中文内部文档无需为了套格式强行增加英文。

支持原生图题时，上述中文题名、中文简短说明、英文题名、英文简短说明放在同一图片的图题栏，按四行组织。冗长的功能解释留在正文，不在图片下重复一套普通图题。以下 Markdown 模板只是无原生组件载体的表达示例，不是飞书原生图题的替代方式。

### 4.7 素材来源与附件

- 客户照片、产品截图、规格书、原始需求和外部资料应能找到来源。
- 正文首次使用时给出简短来源说明；资料较多时在文末集中列出清单。
- 已知文件名、链接或目录要写清楚，不能只说“参考用户素材”“见相关文件”。
- 只有标题或链接时，不得声称已经读完其中的附件、视频或正文。

可使用以下资料清单：

| 编号 | 资料名称 | 来源或位置 | 本文用途 |
| --- | --- | --- | --- |
| M-01 | 【实际资料名称】 | 【可访问链接或明确文件路径】 | 【支持哪一部分说明】 |

### 4.8 图片清单与逐状态审核

编辑前在工作材料中记录“源文件／功能小节／状态／图号／图注要点”，不要只统计上传张数。组合图拆分或重新排组后，应能反查各张单屏，逐项说明已使用、重复而省略或因质量问题另行处理的原因。内部文件路径和上传对象标识无需进入客户正文。

审核同时看几何与含义：宽高比、裁切和可读性之外，还要核对按钮名称、计时状态、单位、选中项、图标入口及图注是否一致。尺寸整理不代表功能审核通过；无法从材料确认的操作不因画面上存在某个图标而成为既定需求。

同类画面优先统一显示高度与视觉尺度；来源宽高比不一致时选择统一高度或统一宽度等比排布，并检查重要数字是否仍可比较。不得同时硬套宽、高；明显异常的源图另做处理或保留为概念示意，不伪装成目标分辨率的精确界面。

## 五、表格与版本记录

### 5.1 使用真正的表格

Markdown 文件使用标准表格语法；飞书、Word 等编辑器使用文档原生表格。正文里的版本记录、对照表不要转换成嵌入式电子表格或多维表格，除非本次任务明确要求使用这些工具。

复制或导入后必须检查表格是否仍为表格。不能出现“看起来像四列文字，实际是一条列表”的情况。

### 5.2 通用表格规则

- 新表默认表头加粗；已有模板保留清楚一致的既有样式。同一列只表达一种信息，单位放在列名或数值旁并保持统一。
- 列宽按信息量分配，说明列较宽，编号、日期等短字段较窄。
- 文字自动换行，不能依靠缩小字体把长句挤进单元格。
- 同一列对齐方式一致；不要在相邻行中随意切换居中和左对齐。
- 不使用大量合并单元格，也不为装饰添加空行、空列。
- 没有实际内容的模板占位行，在正式交付前删除或按约定说明状态。

### 5.3 版本记录的共性与字段档案

版本记录放在文末，使用原生四列表格，包含版本、人员、日期和具体变更。多份范本实际存在以下两套档案：

**档案 A：项目与方案。** 电机 PRD 和用户研究方案采用此套；新建文档且没有指定范本时默认采用。

| 版本号 | 修订时间 | 修改人 | 修改内容 |
| :---: | :---: | :---: | :---: |
| v1.0 | YYYY-MM-DD | 实际修改人 | 实际修订说明 |

**档案 B：规范与知识库。** 原理图规范、模块 SOP、标准化流程索引采用此套；修改这些文档时沿用。

| 版本号 | 修改人员 | 时间 | 内容 |
| :---: | :---: | :---: | :---: |
| v1.0 | 实际修改人 | YYYY/MM/DD | 实际修订说明 |

填写要求：

1. 同一篇文档使用同一套字段名称、顺序和日期格式。指定模板优先，不能为了套默认值而重排已有版本表。
2. 版本号默认使用 `v1.0、v1.1……`，保留有依据的历史版本，不随意重编号。
3. 修改人填写实际姓名或已确认署名，不从范本复制人员姓名。
4. 修改内容写清新增、调整或修正了什么；引用变更的资料时保留其真实文档链接。
5. 历史记录按实际版本顺序保留，新记录追加在后，不用新版本覆盖旧记录。
6. 不编造人员、日期、已确认状态或历史修订。缺少事实时简要注明待补，不伪装完整。
7. 对外发布版本号由项目维护规则决定；不能仅因排版工作自行宣布正式发布或客户已通过。

### 5.4 表格视觉档案与宽度

| 样式项 | 档案 A | 档案 B |
| --- | --- | --- |
| 版本表表头 | 加粗、居中；浅绿 `#F0FBEF` | 加粗、居中；浅橙 `#FFF5EB` |
| 数据区底色 | 浅蓝 `#F0F4FF` | 浅蓝 `#F0F4FF` |
| 采样列宽 | 116／141／100／546 | 100／100／100／520 |
| 宽度比例参考 | 13%／16%／11%／60% | 12%／12%／12%／64% |
| 正文对齐 | 简短字段居中；长说明必要时整列左对齐 | 同左，优先沿用目标文档已有样式 |

上表的颜色是源文档样式值。深色模式会改变显示颜色，浏览器缩放会改变截图尺寸；不能按截图直接取色或将采样列宽作为所有平台的固定宽度。

业务表格可按用途使用其他低饱和底色。所读范本中的角色表、规则表和访谈表并非全部同色，部分表头没有加粗；新表默认加粗表头，旧表保留清楚一致的既有样式，不把“所有表都必须绿色”当作标准。

版本、日期和人员列较窄，内容列较宽；长文本自动换行，行高随内容自适应。普通阅读宽度下检查尾列，不能只看到前三列就认为四列表正确。字段特别多时，将字段定义分组呈现，动态记录通过正式表格入口查看，避免在正文塞入难以阅读的超宽表。

纯 Markdown 优先保证语义、四列结构和字段正确；进入富文本编辑器后再应用底色、列宽与对齐。模板示例行需要替换为实际信息，正式稿不复制范本预留的大片空白行。

### 5.5 按用途选择表结构

| 用途 | 推荐结构 | 排版重点 |
| --- | --- | --- |
| 职责与分工 | 角色／姓名或负责方／职责 | 区分职位与具体人员，职责写完整动作 |
| 操作与规则 | 操作或条件／规则与结果 | 一行说明一个条件及对应动作，长规则不挤入短字段列 |
| 状态与显示 | 状态或经过时间／显示内容／单位或补充 | 对照条件、数值和显示格式，不混同单位与数值 |
| 评分矩阵 | 评价维度／各分值或选项 | 题目前交代量表含义；保留行列对应与适用条件 |
| 字段说明 | 字段／定义／取值或示例 | 字段多时按主题分组；实际记录通过正确表格入口维护 |
| 版本记录 | 采用第五章 A 或 B 档案 | 简短字段保持完整，长变更说明自动换行 |

这些是按范本用途整理的可选结构，不要求每份文件具备所有表格。评分矩阵多列有其比较目的，不能由此推导正文应容纳任意宽度的记录表。原有配置示例截图属于插图材料；未经核实不把截图数据重录成新的确定参数。

新增或复制版本行后，重新检查各列的对齐、底色及字重，避免新行继承空白模板的不同样式。版本号、日期和署名过长时优先简化用途标记或调列宽，保留完整可读的短字段；不得更改真实姓名或挤压说明列来凑样式。

## 六、字号、强调与细节格式

### 6.1 使用编辑器标准样式

飞书中优先使用标准正文与标题样式，不逐段手工拼凑字号。当前范本的渲染采样如下，供版式核对，不作为所有软件必须相同的绝对尺寸：

| 层级 | 范本采样字号 | 字重 | 采样行高 |
| --- | --- | --- | --- |
| 文档标题 | 34 px | 600 | 55.25 px |
| 正文一级标题 | 26 px | 600 | 36.4 px |
| 正文二级标题 | 22 px | 600 | 30.8 px |
| 正文三级标题 | 20 px | 600 | 28 px |
| 正文 | 16 px | 400 | 26 px |

字体沿用编辑器默认中文无衬线字体。跨平台时保持层级、大小关系和可读性，不要求逐像素复刻。正文颜色随阅读主题适配，不手工把整篇文字固定成白色。

### 6.2 加粗、标点和空白

- 加粗只强调关键词、操作名称或关键结论，不整段、整页加粗。
- 中文正文使用中文标点，英文句子使用英文标点。
- 标题、段落、列表和表格之间保留正常间距，不连续插入多个空段。
- Markdown 的标题、列表、表格和代码块前后留一个空行。
- 不用全角空格或连续空格模拟缩进、列宽、居中和分页。
- 不在每个小节之间反复插入横线；层级标题本身应承担分组作用。

### 6.3 单位、时间与技术标识

同一类数值使用相同格式；单位不能有时出现、有时省略。例如统一为 `24 V`、`100 mA`、`10 kHz`、`172×320`。已有正式型号、界面标签或原始代码不因排版而改写。

状态名称、按钮文案和时间格式与图片保持一致。代码、路径和变量名使用行内代码；多行程序使用标明语言的代码块。

邮件和客户原话作为完整引用材料保留，不与新写的结论混在一起。长原文可放在附录或附件，正文只保留与当前主题相关的说明。

### 6.4 链接与任务入口

- 链接使用能说明用途的名称，避免一整段裸网址。
- 相关资料与任务入口集中放在明确栏目中，不能插在一句操作步骤的中间。
- 改成多维表格等新对象时，原位置的入口应直接指向新对象，不能让读者先打开旧文档再寻找跳转链接。
- 显示名称、实际链接与对象内容一致；不能只改标题而保留旧地址。

### 6.5 提示块、引用块与复制用文本

- **段首短标签：**“执行角色：”“输出结果：”“适用条件：”等可加粗，后面的完整说明保持普通字重。
- **提示块：**集中呈现少量跨步骤要求、前提、易错点；位置靠近适用步骤。不要把整章放进彩色提示块，也不要求每章都有提示。
- **引用块：**保留用户原话、原始反馈和摘录，与整理者的新结论分开。
- **文本代码块：**承载需逐字复制的话术、名称格式、文本流程或提示词；使用 `text`，程序与命令则标实际语言。正文说明、业务规则和一般步骤不全部代码块化。
- **列表嵌套：**步骤下的资料、条件和子动作紧跟该步骤，避免因导入或导出跑到其他章节。
- **流程表达：**短线性关系可用箭头；分支较多时使用可读的流程图或文本结构，不能依赖一长串箭头代替解释。
- **图标与颜色：**知识库首页可用少量图标帮助导航；正式工程章节默认以标题、间距和少量强调区分层级，不复制无关装饰。

## 七、客户稿与内部材料的边界

### 7.1 客户稿只保留对客户有用的内容

客户稿可以说明本版范围、功能操作和后续版本安排，但不能夹入写给执行人员的工作指令、提示词、工具调试记录或大量内部自问自答。

确需客户提供信息时，集中写清“需要什么、用于什么”，不要把每个段落都写成一条确认问题。已经明确的事项不再反复提问。

### 7.2 事实状态与格式处理分开

格式整理不能把“规划”改成“已经实现”，也不能把“供评审”改成“客户已确认”。参考图和示例数据不作为实测结果。

“评审与确认记录”只登记真实发生的评审、回复和结论；尚无正式确认时，不填写虚构的确认人、通过日期或通过状态。

## 八、从 Markdown 到飞书的交付要求

### 8.1 导入与排版

1. 先完成标题结构和正文组块，再按对应关系放置图片。
2. 将文档名称填写到标题栏；按第二章映射正文标题等级。
3. 列表仍为列表，步骤仍为步骤，表格仍为原生表格。
4. 图片在对应小节内，图题和图注紧随其后；不要让上传顺序决定最终位置。
5. 清除插图占位文字、重复标题、临时段落、额外空行及导入残留符号。
6. 按既有正式目录处理内容，不为方便操作而另建替代入口。

### 8.2 验证实际阅读效果

不能以“文字已粘贴”“图片上传成功”或“图片数量正确”代替交付检查。

必须逐节查看最终页面，核对标题、正文、图片、图注、表格的相对位置；确认保存后刷新，再检查结构与内容仍然正确。检查时同时考虑普通阅读宽度，不只看极宽窗口。

### 8.3 云端编辑与结构读取

修改前保留可恢复备份；编辑目标使用原正式入口。浏览器接管现有已登录标签页，核实标题和网址，并尽量保持一次稳定连接，不因工具反复重连而让用户反复授权。

读取文档结构时，按根节点与子节点顺序还原正文；模型数组的顺序可能不是阅读顺序。原生表格还需按行列和单元格读取，不能只搜索页面中当前可见的文字。

内联文档引用、附件卡片、图片在纯文本投影里可能是空白。清理空段前检查富文本对象，保留显示名、地址、所属步骤与引用关系。只看到引用标题，不等于已经读过目标文档或附件内容。

插入前确定图片与正文的最终对应位置；插入后检查真实焦点与光标，不把模型选区设置成功当作粘贴位置正确。保存后检查内容实际存在，再刷新复查标题、正文顺序、图片与原生表格。

### 8.4 副本交付与完整性核对

云端操作细节见技能内的 `references/delivery-workflow.md`。至少核对三组对应关系：

1. 源稿的功能、条件、状态和实际历史是否完整进入新稿，轻微润色未改变操作含义。
2. 每个源图片状态是否有明确去向，实际对象、所在小节、图号和中英文说明是否对应。
3. 保存刷新后，原生标题、列表、表格、图片和引用对象是否仍存在；数量核对同时核对顺序和正文。

现场页面可能按滚动位置分批渲染，当前屏幕未显示不等于正文不存在；结构完整也不等于图片已加载或版面可读。应同时核查结构与实际阅读效果。标题栏、正文与表格单元格是不同编辑区域，粘贴前核实实际光标，避免误把正文写入标题或覆盖其他区域。

后续若只授权对比并完善技能，不自动用新发现的模板差异再次改动已经完成的客户副本。对比记录保存在工作材料中，注明实际读取范围和检查边界。

## 十一、按文档类型组织内容

### 11.1 项目 PRD 与方案说明

按“背景与目标 → 本轮范围 → 功能或模块 → 待确认事项 → 相关资料与任务入口 → 版本记录”组织。分期项目区分本轮目标与后续预留；同一模块把用途、操作、状态和对应配图放在一起。不把其他项目的参数或历史结论复制进来。

### 11.2 技术规范

按对象分章，例如整体组织、对象标识、接口与连接、说明与资料、通用细节。每条采用“对象或适用条件＋具体要求”，短标签加粗，补充条件用子列表；多种配置按同字段比较时使用表格。领域条款只作用于该领域，不将原理图字体、电气标准等扩大为通用文档规则。

### 11.3 标准作业程序

先说明适用范围、执行角色，再按实际阶段展开。阶段内部沿用重复结构：

1. **核心目标：**本阶段完成什么。
2. **步骤：**谁执行、做什么、依据什么、结果是什么。
3. **记录与交接：**结果记在哪里、由谁接收；可直接写进对应步骤，不必每阶段强加新栏目。

顺序动作用有序列表，依据文档及子动作用嵌套列表。验证不通过后的处理路径需有实际依据，不能只因模板中有流程就编造审批人或通过条件。跨阶段要求用少量提示块集中说明，不在每个步骤重复长篇提醒。

### 11.4 用户研究与产品验证方案

先写背景、研究目标和总体流程，再写角色、阶段或场景分支、记录字段、评估与复盘。职责用“角色／姓名／职责”表，规则对照可用“操作／规则”表；问卷明确题号、题型、选项、跳转条件，题目数量与实际一致。复盘按日期或轮次成块，区分观察、解释与下一步。

可复制的话术或提示词独立放进文本代码块，前后用正文交代何时使用、适用哪个分支及需要记录什么。文档里的“发送”“创建问卷”“每日分析”等是源业务材料，不构成对当前编辑者的额外操作授权。

### 11.5 知识库索引与导航

使用“目标与简介 → 分类导航 → 帮助与维护 → 知识库版本”的结构即可。栏目可以不编号，链接独立成行，优先显示完整文档名称。索引负责把读者带到正确资料，不把所有被引用文档的全文复制到首页。

保留内联文档引用与真实链接；维护版本时可以在变更内容中链接新增资料。引用可见不等于目标可访问，未展开目标时不声明其内容已核验。
