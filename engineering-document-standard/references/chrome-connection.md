# 连接现有 Chrome 与复用会话

## 先判断宿主能力与执行位置

宿主指 AI 所在的软件及其工具执行环境。工具名可以不同，先按实际能力选择方式，不要求其他 AI 提供本机同名接口。

| 已确认的能力 | 选择方式及前提 |
| --- | --- |
| 浏览器插件能够枚举用户当前 Chrome 的标签页 | 使用插件并核对目标；无需启动随包脚本 |
| 可以跨步骤保留本地进程及标准输入 | 可使用随包交互脚本；记录当前会话句柄，后续输入发送到同一进程 |
| 只能执行一次性命令 | 优先使用已安装且支持持久会话的客户端或浏览器插件；按该工具文档核实后台会话如何保留，不反复启动交互脚本 |
| 工具在远程服务器、容器或隔离环境执行 | 先核实能否通过已有、获授权的通道访问 Chrome；运行脚本的机器不一定是用户电脑 |
| 未发现可用浏览器控制工具，也无法运行本地客户端 | 说明缺少的实际能力或连接通道；不能把无法控制当成已连接，也不能改用无登录的新浏览器冒充当前会话 |

`127.0.0.1` 和本地文件路径属于执行客户端的环境。远程或隔离环境不能据此定位用户电脑；没有通道时不擅自对外开放调试端口、不更改监听范围。用户允许的本地连接组件或已有插件可提供通道，技能文字本身不能创造网络可达性。

技能应按完整目录分发，保留 `SKILL.md`、`references/`、`scripts/` 的相对结构。安装位置由接收方现场解析，不硬编码某个 AI 产品的技能目录。引用资源不可访问时，确认现有工具能否独立完成任务；不能把文档中的示例路径当作真实安装位置。

## 选择方式

先只读检查本对话已有连接的状态、标签页标题和完整网址。有可用连接时继续使用；不要为测试其他工具额外建连接。旧对话中的进程号、页面 ID、端口文件内容只是历史证据，需要现场重查。

没有连接时，根据实际可用能力选择以下任一种方式。切换方式的依据是已观察到的错误，不是固定轮试所有工具。

- 浏览器插件：读取工具说明，枚举现有标签页，确认它控制的是用户当前 Chrome。工具名、插件已安装或能打开新页面，都不能证明已接管当前登录会话。
- `agent-browser`：先检查命令搜索路径及项目已有安装；Windows 项目可能有 `.tools/agent-browser/node_modules/agent-browser/bin/agent-browser-win32-x64.exe`，这是可选位置，不能假设每台机器都有。用实际可执行文件运行 `skills get core`，遵循该版本指南。每个任务使用命名会话，后续命令沿用同一会话；共享 Chrome 时固定目标标签页。常见形式为 `agent-browser --session <本任务名称> --auto-connect tab --json`，随后 `--session <同一名称> tab <本次返回的标签页标识>`。如果版本提供 `--pin-tab`，绑定确认后的目标。端口连接只用现场发现的端口，不默认 9222。遇到异常按该版本的 `doctor` 指南诊断，不自动执行破坏性修复。
- 直接 CDP：从实际 Chrome 数据目录中的 `DevToolsActivePort` 读取浏览器级 WebSocket 地址，或使用用户/工具已提供并核实的端点。可以用随包脚本，也可以用当前运行时支持的 CDP 客户端；不强制某种语言。`Target.getTargets` 枚举后核对目标，通过 `Target.attachToTarget({targetId,flatten:true})` 附加；页面命令的 `sessionId` 放在协议消息顶层。

## 首次使用与授权

Chrome 144 及以上的现有会话连接流程，需要在 `chrome://inspect/#remote-debugging` 启用，并由用户允许连接请求。没有启用或存在企业限制时，说明准确阻碍；不能用循环连接代替设置与授权。旧式 `--remote-debugging-port` / `--remote-debugging-pipe` 自 Chrome 136 起对默认数据目录有限制，不应拿旧命令去重启用户的默认浏览器。

尽量少弹授权框：复用已成功或正在等待授权的同一连接；不要每一步重启客户端，不要同时测试多个客户端。若提示正在等待用户允许，只说明一次，保留进程并用空输入读取后续状态，不重复发起连接。没有看见弹窗不等于授权已拒绝，现有 Chrome 可能在后台。用户明确拒绝后停止；等待进程已失效时，先确认清理完成，再根据当前状态重试一次。不得关闭授权检查或承诺永久免确认。

## 可选随包脚本

脚本位置为本技能的 `scripts/chrome-session.cjs`。先确认实际安装目录及可用 Node.js；`node -p "typeof WebSocket"` 应为 `function`。某些内嵌 JavaScript 环境没有该全局接口，不能以系统 Node.js 的版本推断它也有。可改用系统 Node.js 或其他可用客户端，无需为了本技能安装依赖。

```text
node "<技能绝对目录>/scripts/chrome-session.cjs" --discover
node "<技能绝对目录>/scripts/chrome-session.cjs"
node "<技能绝对目录>/scripts/chrome-session.cjs" --file "<实际 DevToolsActivePort 文件>"
node "<技能绝对目录>/scripts/chrome-session.cjs" --endpoint "<已核实的 ws:// 或 wss:// 浏览器端点>"
```

`--discover` 只检查本地文件，不连接浏览器，不触发授权。脚本自动检查 Windows、macOS、Linux 对应的 Chrome Stable 数据目录；支持 `CHROME_USER_DATA_DIR` 指定根目录，其他通道或自定义目录使用 `--file`。Windows 同时检查环境目录和实际用户目录，以应对环境变量重定向。存在多个有效候选文件时要求明确选择，不擅自决定用户的浏览器。文件存在不保证端点仍在线；脚本不会自动重连。

交互脚本的必要能力是：启动后进程保持运行、标准输入持续开放、后续步骤能向同一进程输入并读取输出。在提供 `exec_command` / `write_stdin` 的宿主中，可用 `tty:true` 启动并保存返回的 `session_id`；这些名称仅是适配示例，不是技能对所有 AI 的接口要求。其他宿主按自身文档使用等效机制。若宿主在单次命令后就关闭输入，不选这个脚本逐步操作，改用已核实可保持会话的客户端或插件。

看到 `CHROME_CONNECTED` 后逐行执行，每行等待结果；Windows 交互终端行尾用 `\r`，普通管道用 `\n`。只有回显时继续读取输出，不重发尚未确认结果的命令。

```javascript
tabs()
attach('<本次核对后的 targetId>')
ev('({title:document.title,url:location.href})')
status()
```

脚本提供 `ev(expression)`、`click(x,y,button)`、`screenshot(absolutePath)`、`cdp(method,params,sessionId)` 和 `delay(ms)`。复杂流程用 `(async()=>{ ... })()`，不要直接输入顶层 `await`。页面操作前重新查 DOM（文档对象模型）和元素位置；点击坐标使用 CSS（层叠样式表）坐标，不直接套截图像素。截图需存在且可写的父目录。

脚本的 EOF（输入结束）会释放连接，避免留下不可交互的控制进程；宿主需持续保留标准输入。日志不打印 Cookie、令牌或浏览器存储。

## 连接生命周期与回复边界

同一项连续浏览器工作中的读取、分析、修改、核验及紧接的后续操作应复用已有效的控制会话。一次工具返回、中间进度说明或阶段性回复不自动代表整项工作结束；不要仅因这些边界发送 `close()`、终止进程或创建替代会话。

明确整项工作已经完成、用户要求断开，或宿主必须回收资源时，释放自己持有的连接。随包脚本使用 `close()`，其他工具按各自说明断开；不调用 `Browser.close` 关闭用户浏览器。宿主无法跨回复保留会话时说明限制，不承诺继续复用已回收的进程。新对话先检查工具实际保留的连接并重新枚举目标，不能照抄旧会话句柄。新的连接仍可能需要 Chrome 授权。

## 按错误处理

| 现象 | 处理 |
| --- | --- |
| 命令不存在、全局 `WebSocket` 缺失、输入通道关闭 | 修正工具路径、运行时或进程启动方式；属于客户端问题，不能据此认定浏览器不可控 |
| 文件不存在或格式无效 | 核实实际系统、通道、自定义数据目录及远程调试状态；使用 `--discover` 或明确的文件路径，不硬编码个人用户名 |
| `/json/list` 返回 404 | 某些连接模式仍支持文件里的浏览器级 WebSocket；可以改用 `Target.getTargets`，不能单凭 HTTP 路由失败宣告连接失败 |
| `ECONNREFUSED`、端点关闭 | 重读现场端点，确认浏览器在运行；按证据选择其他方式，不循环重试 |
| 超时 | 区分握手等待授权、协议响应超时与页面加载；查询进程/连接状态。只回显时继续读取，不重复发送写入 |
| 403、`EACCES`、拒绝授权 | 区分浏览器授权、操作系统和宿主权限；遵守相应权限流程，不复制浏览器配置绕过 |
| 写入或提交后断线 | 先读回服务器/页面状态，再决定下一步；不自动重放上传、创建、发送或删除 |
| 附加的标签页被关闭 | 脚本收到匹配的 `Target.detachedFromTarget` 后清除缓存会话，浏览器级连接继续复用；重新枚举后直接附加另一个目标。旧会话失效的通知不能清除新目标的会话 |

验收需证明：连接当前会话 → 核对目标 → 完成授权范围内操作 → 读回结果。静态语法检查、文件存在或控制横幅均不能代替实际验收。只读连接验证可枚举标签页、读取文档、滚动并恢复位置、截图；没有业务修改需求时不额外编辑文档。

会话生命周期回归测试使用 Node.js 内置测试运行器，无需浏览器授权：`node --test "<技能绝对目录>/scripts/tests/chrome-session.test.cjs"`。测试覆盖关闭标签页、迟到或无关的通知、旧会话失效竞态及其他协议错误；它不能代替实际 Chrome 验证。

依据：[Chrome 现有会话连接与授权](https://developer.chrome.com/blog/chrome-devtools-mcp-debug-your-browser-session)、[旧式远程调试参数限制](https://developer.chrome.com/blog/remote-debugging-port)、[CDP Target 域](https://chromedevtools.github.io/devtools-protocol/tot/Target/)。工具命令以实际安装版本的指南为准。
